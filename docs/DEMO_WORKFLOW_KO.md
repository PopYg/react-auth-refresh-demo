# 데모 작업 운영 가이드 (공통 재사용)

## 목적
- 이 문서는 이력서용 프론트엔드 데모를 연속으로 만들 때 기준이 흔들리지 않도록 작업 규칙과 완료 이력을 고정해두기 위한 문서입니다.
- 다음 데모를 시작할 때 이 문서를 복사해서 같은 구조로 진행합니다.

## 공통 기준
- README 기준 문서는 `README.md`(한글)로 유지합니다.
- `README_EN.md`는 한글 기준 문서 안내 용도로 최소 유지합니다.
- README 타이틀/섹션 타이틀은 한글로 작성합니다.
- README에 불필요한 날짜 메타데이터는 두지 않습니다.
- NDA 대상 실무 코드/API/고유 식별자는 공개 데모에 포함하지 않습니다.

## Git/배포 기준
- 저장소 기본 브랜치: `main`
- 커밋 메시지: 한글 중심으로 작성
- 공개 리포 푸시 전 필수 확인:
  - `git status`
  - `npm run build`
  - README 한글 타이틀/섹션 점검

## 현재 데모 완료 이력 (react-auth-refresh-demo)
- 인증 기본 흐름 구현:
  - 로그인/로그아웃
  - 토큰 저장소(`tokenStore`) + 인증 컨텍스트(`AuthContext`)
  - 보호 라우트(`ProtectedRoute`)
- 토큰 갱신 흐름 구현:
  - axios 요청 인터셉터로 `Authorization` 자동 주입
  - axios 응답 인터셉터에서 401 처리
  - `single-flight refresh`로 동시 401에서 refresh 1회만 실행
  - refresh 성공 시 원요청 자동 재시도
- mock adapter 보정:
  - 비정상 상태코드에서 `AxiosError`를 throw하도록 수정해 401 분기가 인터셉터로 정상 진입
- 대시보드 정리:
  - 인증 검증과 무관한 `Documents`, `Event Log` 제거
  - 지표 카드 자동 갱신(`/auth/debug/stats`, 2초 주기)
  - 버튼 동작/예외 처리 보정
- UI/문구 정리:
  - 주요 UI 한글화
  - 보조 문구/불필요한 표시 텍스트 제거
- 문서 정리:
  - README 본문/타이틀 한글 통일
  - 영문 README를 한글 기준 안내 형태로 최소화

## 다음 데모 시작 체크리스트
1. 저장소 생성 후 `main` 브랜치 기준으로 초기화
2. 데모 목적을 한 문장으로 먼저 확정 (문제 중심)
3. mock API/상태 모델을 먼저 정의한 뒤 UI 연결
4. 핵심 시나리오를 3~5개로 제한하고 버튼/상태로 검증 가능하게 구성
5. README를 같은 섹션 구조(한글 타이틀)로 작성
6. `npm run build` 통과 후 커밋/푸시
